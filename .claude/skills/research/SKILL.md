# Исследование

Методика: `method/03-research.md`.

1. Для каждого вопроса из брифа: что говорят источники, где они расходятся, какой вывод.
2. Вывод — `ledger.py add K --text ... --based-on C..`. Промежуточные выводы — `C --type inference`.
3. Противоречия между источниками не прячь: заведи оба утверждения, одно пометь `dispute`.
4. Гипотезы, которые можно проверить открытыми данными (отзывы, скриншоты, публичные условия),
   проверь сразу: `ledger.py verify C<n> --result ... --sources S.. --note "..."`.
   Гипотезы об учебном операторе из брифа открытыми данными не проверяются: итог — `inconclusive`
   с пометкой «нужны данные оператора» и способом их получить (`method/10-brief.md`).
   Попроси субагента **auditor** проверить 5–10 ключевых фактов по источникам и опоры выводов по смыслу. Его
   замечания → `dispute`/`revoke` и правка выводов.
5. (Доп. уровень) Если нужны гипотезы о мотивах пользователей — субагент **persona**,
   ответы только как `synthetic` (method/06-synthetic.md). Когда историй клиентов нет (учебный бриф),
   persona помогает составить вопросы для интервью и версии причин, но **не заменяет** восстановленный
   случай клиента и не доказывает частоту.
6. Запиши `output/03-situation.md`: **Что известно** (со ссылками `[C..]`), **Откуда**,
   **Чего мы не знаем и почему**, **Что изменило бы картину**.
7. `ledger.py validate`, `ledger.py report`, обнови `state.md`.
