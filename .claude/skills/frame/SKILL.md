# Постановка задачи

Методика: `method/01-framing.md`.

1. Разбери запрос по пяти полям: **вопрос**, **цель** (какое решение будет принято),
   **получатель** результата, **ограничения** (срок, бюджет, что нельзя), **доступные данные**.
2. Заполни то, что можно вывести из запроса сам. Спроси только то, без чего нельзя
   сделать следующий шаг — **не больше 3 вопросов**, с вариантами ответа.
3. Сформулируй **вопросы, которые могут изменить решение** (3–6 штук) — это план исследования.
   **Проверь посылку запроса**: если запрос предполагает факт («удержание падает»), а данных
   нет — запиши его как `hypothesis` и скажи пользователю.
   Выбери методы по типу вопроса (`method/00-toolkit.md`) и запиши в бриф, зачем каждый.
   Если задача — стратегия, уточни три вещи из `method/09-practice.md`, раздел 1: была ли прежняя
   стратегия и почему не сработала; что заказчик понимает под результатом (план релизов, продукт,
   весь бизнес); позиция главного заказчика. Чего не знаем — в «Чего мы не знаем».
   **Если есть бриф** (`briefs/` или файл пользователя): сохрани его в `sources/` проекта, зарегистрируй
   как источник; заданные в нём числа и определения — записи реестра с этим источником (учебные числа —
   с пометкой «учебные»); требуемую структуру итогового документа и решения руководителя по срокам —
   в `01-brief.md`. Не спрашивай то, что бриф уже сказал.
4. Каждый ответ пользователя → `ledger.py add C --type user_input ...`.
5. Запиши `output/01-brief.md` по шаблону из методики и покажи пользователю краткую версию.
6. **Точка подключения человека:** попроси подтвердить постановку перед сбором материалов.
7. Обнови `state.md`: этап 1 — готово, следующий — `/gather`.
