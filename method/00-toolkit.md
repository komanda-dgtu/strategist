# Набор методов и когда что применять

Агент не применяет все методы подряд — это лишняя стоимость и шум. Он выбирает методы
по **типу вопроса** (маршрутизация методов) и записывает выбор в `output/01-brief.md`.

## Каркас процесса
| Этап агента | На что опирается |
|---|---|
| Постановка | Issue tree и гипотезо-ориентированный подход (McKinsey; Minto, «Принцип пирамиды»), принцип MECE; «вопросы, меняющие решение» (decision-driven research) |
| Исследование | Double Diamond (UK Design Council): сначала расширяем понимание, потом сужаем; Continuous Discovery и Opportunity Solution Tree (Teresa Torres) |
| Источники | Иерархия доказательств и разделение факт/оценка/прогноз; Analysis of Competing Hypotheses (Heuer, разведаналитика) — ищем данные, которые опровергают гипотезу, а не только подтверждают |
| Варианты | Обязательные «как есть» и «закрыть»; pre-mortem (Gary Klein) и красная команда для возражений; «что должно быть правдой» (Roger Martin, Playing to Win) |
| Стратегия | Playing to Win (где играем, как выигрываем); позиционирование (April Dunford); Value Proposition Canvas (Strategyzer) |
| Проверка | North Star и дерево метрик; Google HEART для UX-метрик; эксперименты с контрольной группой и guardrail-метриками |

## Маршрутизация по типу вопроса
| Тип вопроса (из Контекста задания) | Основные методы | Файл |
|---|---|---|
| «Почему падает удержание» | дерево метрик удержания по этапам жизни подписчика (пробный → 1-й платный → n+1 → возврат); когортный анализ (если есть данные); CJM с точками оттока; JTBD «увольнение продукта»; анализ отзывов по причинам; конкурентные альтернативы; проверка «меняет ли вариант ключевой сценарий» | 03, 07, 08, 09 |
| «Кому и как продавать новый сервис» | JTBD и сегментация; размер рынка TAM/SAM/SOM; ценность vs альтернативы; ценовая чувствительность (Van Westendorp как гипотеза); позиционирование | 03, 05, 08 |
| «Что сказать аудитории, чтобы поняла ценность» | барьер понимания/выбора; messaging house (ключевое сообщение → опоры → доказательства); See–Think–Do–Care (Google) для роли каналов; CJM этапа выбора | 05, 07 |
| Контекст рынка (любой вопрос) | PESTEL — только факторы, которые меняют решение; 5 сил Портера — для оценки привлекательности направления | 08 |
| Приоритизация внутри варианта | RICE / ICE с явными оценками как ПРОГНОЗ | 04 |

## Сбор данных о пользователях
| Метод | Что даёт | Чего НЕ даёт |
|---|---|---|
| Отзывы в сторах и отзовиках | реальные формулировки проблем, частые жалобы | долю пользователей с проблемой |
| Публичные исследования (агентства, опросы) | масштаб, динамику рынка | причины поведения конкретного продукта |
| Анализ интерфейса по скриншотам | где путь ломается (UX-эвристики Нильсена) | как часто это происходит |
| Реальные интервью (The Mom Test, Rob Fitzpatrick) | мотивы, прошлое поведение | статистику |
| Модельные респонденты | гипотезы и формулировки | доказательство спроса — никогда |
| Внутренние данные компании | когорты, отток, ARPU | в рамках задания недоступны — только как пробел и план проверки |

## Практика российских команд
`method/09-practice.md` — выводы из открытых докладов ProductSense: вопросы до стратегии, удержание
подписки по этапам (опыт ivi), пределы уведомлений, акции без каннибализации, количественная оценка
сегмента, дешёвые проверки до A/B. Сведения оттуда в реестре — `opinion`.

## Ограничение
Методы — инструмент, а не цель. В документах указываем метод только там, где он повлиял на вывод.
