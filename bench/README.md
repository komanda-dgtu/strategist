# Сравнение «Стратега» с обычным чатом: пересмотр при новых данных

**Вопрос, на который отвечаем.** Если меняется одно ключевое сведение, помогает ли агент руководителю
продукта быстрее и надёжнее пересмотреть решение, чем обычный чат с хорошим промптом?

Сценарий взят из упражнения по книге Ю. Билинкис «Управление продуктом: российская практика»
(как проверить стратегию самого продукта) и адаптирован под кейс МегаКино.

## Порог — записан до запуска
Ставку на сценарий «пересмотр при новых данных» пересматриваем, если обычный чат на тех же материалах
одновременно:
1. находит не меньше затронутых выводов из эталонного списка, чем агент;
2. не теряет независимые подтверждения (не меньше, чем агент);
3. требует от человека почти столько же активного времени: разница меньше трети.

Тогда в демо упор не на пересмотр, а на разметку «факт / гипотеза / мнение» и обязательные варианты
«оставить» и «закрыть».

## Материалы — одинаковые для обоих прогонов
- `projects/megakino-bench/output/` — пять файлов: `04-options.md`, `05-strategy.md`, `06-decisions.md`,
  `econ.md`, `evidence.md` в состоянии до пересмотра (снимок делается шагом 1).
- Новое сведение — `bench/new-data.md`. Это **учебное допущение**, а не факт: в основной реестр оно не попадает.

## Порядок
1. **Снимок.** Скопировать папку проекта: `cp -r projects/megakino-retention projects/megakino-bench`.
   Агент работает только с копией; основной проект не трогается.
2. **Эталон до запуска.** Человек, не глядя на ответы, отмечает в `bench/scorecard.md`, какие выводы
   должны измениться. Черновик эталона там уже есть — его нужно проверить и поправить.
3. **Прогон А — обычный чат.** Новый чат на claude.ai (не в Cursor: там агент видит весь проект).
   Приложить пять файлов из «Материалов», вставить `bench/chat-prompt.md`, затем `bench/new-data.md`.
   Засечь активное время человека: чтение, вопросы, правки. Ожидание ответа не считаем.
4. **Прогон Б — агент.** Cursor, папка `strategist`, новый чат: «Переключись на проект megakino-bench
   (`ledger.py use megakino-bench`). Вот новые данные: …» (текст из `bench/new-data.md`) и `/revise`.
   Засечь активное время так же. После прогона вернуть основной проект: `ledger.py use megakino-retention`.
5. **Оценка.** Заполнить `bench/scorecard.md` по обоим прогонам. Лучше, если оценивает второй человек,
   не знающий, где чей ответ (ответы переименовать в «Ответ 1» и «Ответ 2»).
6. **Итог.** Сравнить с порогом. Записать вывод в `bench/result.md` и в PDF-описание — каким бы он ни был.

## Что смотрим
| Критерий | Как считаем |
| --- | --- |
| Найдены затронутые выводы | сколько из эталонного списка названо как требующие пересмотра |
| Ложные тревоги | сколько названо затронутыми, хотя они не зависят от нового сведения |
| Независимые подтверждения сохранены | выводы, которые держатся и на других источниках, не выброшены целиком |
| Объяснимость | человек за 2 минуты своими словами объясняет, почему изменился выбор, и называет опоры |
| Новые утверждения без источника | сколько в обновлённом тексте фактов, у которых нет источника |
| Активное время человека, мин | по секундомеру |
| Стоимость | токены из `usage.py report` (Cursor) или число сообщений (чат) |
