# Каскад моделей для массовой разметки: дешёвая модель → основная

**Вопрос.** Задание поощряет «специализированные модели, которые выбирают, классифицируют или оценивают
по признакам», и выбор модели «по задаче, качеству и стоимости». Можно ли массовую разметку (отзывы,
обращения) отдать дешёвой модели, а основной — только сомнительные случаи, и что это даёт в качестве и цене?

**Почему не Jev.** Специализированная модель Jev (TypeSafe) из России недоступна: регистрация не проходит,
а сервис, который жюри не сможет запустить по инструкции, делает работу невоспроизводимой. Подход взят
из кейса «Decision Models» AI-мастерской GoPractice (своими словами, без текстов курса): разложить решение на
маленькие вопросы с вариантами ответа, эталон — от человека, порог уверенности подбирать на обучающей
выборке и проверять на тестовой, сравнивать пайплайны по качеству и цене.

**Порог, записанный до прогона.** Каскад считаем полезным, если на тестовой выборке он не больше чем
на 3 п.п. хуже основной модели по каждому вопросу и дешевле её хотя бы на 30%. Иначе — массовую разметку
оставляем основной модели и пишем это в описании работы.

## Данные
Свежие отзывы о приложении МегаФона в RuStore (открытый API), 300 штук, без имён авторов, номера скрыты.
Тексты лежат в `data/` и не публикуются; публикуются скрипты, вопросы и итог (`result.md`).

## Порядок (около 40 минут, из них вашего времени — 20)
Все шаги — в Cursor, папка `strategist`.

1. **Новый проект для учёта токенов.** Чат агента (любая модель):
   > Создай проект для замера: `python3 scripts/ledger.py new cascade-bench "Каскад моделей для разметки отзывов"`.
   > Затем выполни `python3 bench/cascade/fetch_rustore.py` и `python3 bench/cascade/make_sets.py`. Больше ничего не делай.
2. **Ручной эталон (вы, ~15 минут).** Откройте `bench/cascade/data/gold_sheet.csv` и заполните столбцы
   `q1`, `q2`, `q3` для 30 отзывов по правилам из `bench/cascade/questions.md`. Не советуйтесь с агентом:
   это эталон человека.
3. **Три прогона разметки — три новых чата**, в каждом сначала выбираете модель в списке под полем ввода,
   потом вставляете один и тот же запрос (заменив `<имя>`):
   - чат 1: модель **Grok 4.6 High Fast**, `<имя>` = `cheap`;
   - чат 2: модель **Grok 4.7 High Fast**, `<имя>` = `main`;
   - чат 3: модель **Claude Opus 5.5**, `<имя>` = `judge`.

   > Разметь все отзывы из `bench/cascade/data/batch.jsonl` по правилам `bench/cascade/questions.md`.
   > Ответ на каждый отзыв — одна строка JSON в формате из questions.md, с уверенностью для каждого вопроса.
   > Запиши все строки в `bench/cascade/data/labels_<имя>.jsonl`. Не пиши скриптов-эвристик и не открывай
   > файлы labels_* других моделей: размечай сам, читая отзывы. Файл gold_sheet.csv не открывай.
4. **Цена.** Откройте cursor.com → Dashboard → Usage и выпишите стоимость каждого из трёх чатов в долларах
   (даже если она входит в подписку).
5. **Итог.** Чат агента:
   > Выполни `python3 bench/cascade/score.py --project cascade-bench --usd cheap=<$>,main=<$>,judge=<$>`
   > и покажи `bench/cascade/result.md`. Затем верни основной проект: `python3 scripts/ledger.py use podpis-nomera`.

Если модель в учёте записалась под другим именем (видно в `projects/cascade-bench/costs/cursor-turns.jsonl`),
передайте его в `--models cheap=<имя>,main=<имя>,judge=<имя>`.

## Чего этот замер не покажет
- Уверенность модель называет словами; это не вероятность, как у специализированных моделей. Поэтому порог
  подбирается на обучающей выборке, а проверяется на тестовой.
- Токены Cursor включают общий контекст агента (правила, состояние проекта), а не только тексты отзывов.
  Поэтому главное сравнение — доллары из панели Usage, а токены — для порядка величин.
- 30 отзывов ручного эталона — мало для точных процентов; это проверка, можно ли доверять судье.

## Итог прогона 17.11.2026

Цифры — `result.md` (пересобирается `score.py`). Модели: дешёвая `cursor-grok-4.6-high-fast`, основная
`grok-4.7-high-fast`, судья `claude-opus-5-5-medium`; 300 отзывов RuStore за 21.10–17.11.2026.

| Главная тема, 5 вариантов | 73% / 67% / 67% | 86% / 93% / 91% (17%) |

Токены на 1000 отзывов (вход + выход): дешёвая 1,72 млн, основная 2,33 млн (−26%); каскад для темы
≈ 2,11 млн (−10%). При подписке Cursor стоимость каждого запроса показана как «Included», поэтому
сравнение в долларах недоступно; токены — для порядка величин.

**Вывод по порогу, записанному до прогона.** На вопросах «да/нет» критерий выполнен: дешёвая модель
не хуже основной и тратит на четверть меньше токенов — её и закрепили за субагентом `classifier`.
На теме каскад на 2 п.п. хуже основной (в пределах 3 п.п.), но экономит только 10% токенов — меньше
порога 30%: экономия по токенам не доказана.

**Главная находка.** На теме все три модели совпадают с человеком лишь в 67–73% случаев, почти все
расхождения — «приложение» против «другое». Ограничение — в определении вариантов, а не в модели;
следующий шаг — уточнить определение на обучающей выборке и только потом выбирать модель.

**Сбои при замере.** Чат основной модели записал ответ в файл дешёвой (в запросе осталось `cheap`);
файл переименован, дешёвая модель размечала повторно, первый её прогон из токенов исключён (`--skip-gen`).
Правило автоподбора порога («не хуже основной на 2 п.п. на обучающей») выбрало 0,5 — на тестовой
лучше 0,7, это видно в таблице порогов `result.md`.
